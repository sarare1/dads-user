⬤ Sequence Pipeline (pulse trains)
Sequence Dataset (de-interleaved tracks)
Ordered pulses of one emitter per track — what a de-interleaver delivers — for training and testing the sequence models (Training page). Each track carries its family's PRI pattern and frequency agility over time. A fresh random population of radar families and held-out classes is drawn every time you click Generate. No time of arrival: only the PRI sequence. Frequency in Hz.
Classes: how many distinct radar families exist in total; the model's classifier head is sized to match. Holdout: families never trained on, used to test open-set rejection. Missed: a pulse not intercepted — the next PRI becomes the sum of two intervals. Spurious: another emitter's pulse wrongly assigned to the track by the de-interleaver. Noise tracks: tracks with no coherent emitter (unknown, like held-out families) — never used to train, only to evaluate.
Advanced: Population Ranges
Physical parameter spans the radar families are drawn from. Leave defaults to match the original ranges; narrow them for a harder/more separable task.
Each family's pulse width follows from its duty cycle: PW = duty × PRI, the duty cycle drawn (log-uniformly) from this range — so a pulse is never longer than the interval between pulses. Pulse Width Min/Max still limit the result (the duty-cycle range wins if both can't hold for a family's PRI).
Extra features (your own columns)
Add columns of your own to every generated pulse. Numeric: each family gets its own value between Min and Max, and its pulses scatter around it by the given noise %. Categorical: each family gets one of the comma-separated values. The columns sit between timeBW and instance in the file, and then appear on the Training page as features (numeric: the value and its change from pulse to pulse; categorical: the category) — so the same feature is used in Training, Testing and Inference.
PGRI = Pulse Group Repetition Interval: a family transmits groups of 2–8 pulses at a short intra-group PRI, then a long gap; groups repeat every PGRI. When ticked, about 1 in 7 families use it (group shape fitted so pulses within a group never overlap), in addition to constant, jittered, staggered, sliding, wobulated and dwell-and-switch. Recorded with the dataset and each model, so older datasets/models keep regenerating exactly as before.
Or Upload Your Own Tracks
One row per pulse, columns in this order: Frequency (MHz), PW (µs), PRI (µs), Modlntype (text), Modlnval, snr (dB), rise (ns), fall (ns), timeBW (Hz), your own extra columns, instance (the track: class name + capture date, text), class (emitter name; UNKNOWN… = unknown), then the bookkeeping columns pulse_idx (order within the track; optional) and true_class_id (optional; derived from class, −1 = unknown). Only the columns you have are needed. The first pulse of a track may have a blank PRI. Files written with the older names (track_id, true_label, pri_us, carrier_freq_mhz …) are converted on upload.
Grow a Small Dataset into a Large One
Pick a stored dataset (for example your uploaded one). Every class is topped up to the number of tracks you ask for: each new track starts from one of the class's own tracks at a random point of its pulse pattern, and — when the class has several tracks — differs by the spread the class's real tracks show. No noise is added (your data is already clean). The source dataset is not changed; the result is stored as a new dataset.
All Datasets
Every generated or uploaded dataset is kept under its name. Training, Testing and Analytics each let you choose from this list, and every trained model remembers which dataset it learned from. “Default” is what the Training page offers first. Deleting a dataset does not touch models already trained on it.
