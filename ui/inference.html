Track Input
The ordered pulses of one emitter (or several tracks), as a de-interleaver delivers them — one CSV row per pulse: instance (the track; optional for a single track), pulse_idx, and the measurements the model was trained on (Frequency in MHz, PW, PRI, Modlntype, Modlnval, snr, rise, fall, timeBW in Hz, plus any extra feature columns). The first pulse may have a blank PRI. No time of arrival needed.
Generate an example track

Automated ECM Action:-
The network always names its closest known family — even for a track it does not recognise. So when the verdict is not “verified known”, the class is shown as “UNKNOWN (nearest known: …)”: for unknown or noise tracks the same look-alike family tends to come up every time, which is expected and not a classification. Track class = majority vote over its windows of k consecutive pulses; verdict = most common window verdict (a window is verified known when confidence ≥ τ_c and distance ≤ τ_d).
Decision as pulses arrive
The decision on the last ≤ k pulses after each new pulse — what Live Simulation shows. With few pulses there is no pattern to see; confidence and distance settle as the PRI pattern and frequency agility emerge. Point colour = verdict.
