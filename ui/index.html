Shared Training Settings
How “far apart” two embeddings are. It is used in two places, nothing else: (1) the triplet loss while training pulls windows of the same family together and pushes different families apart by this distance; (2) afterwards, a window's distance to its nearest class prototype is measured the same way and compared with τ_d to decide “known” or “unknown”. It is plain arithmetic on the model's output vectors. Cosine is the usual choice; euclidean picks the same nearest prototype (the vectors have length 1) but on a different distance scale, so τ_d must be chosen to match. (Runs from before v1.2.0 may show “dot”: that was always computed as cosine.)

Reciprocal Points (RPL / ARPL)
How strongly the auxiliary RPL open-set objective shapes the shared embedding space during training, relative to the primary classifier + triplet losses. Higher lets RPL converge faster but risks pulling the embedding space away from what the primary threshold method wants.
Adds a generator network that adversarially synthesizes "confusing" embeddings targeting each known class, trained alongside the classifier in a min-max game — the classifier learns to keep rejecting them as open-space even as the generator tries to make them pass. Tightens RPL's decision boundaries beyond the passive open-space margin loss alone, at the cost of a less stable, sometimes slower-converging training run. Off by default (plain RPL) — turn on for a genuine RPL-vs-ARPL comparison across two training runs.
Applies to the next training run; trained models are unaffected. Backbone, window, features and embedding size are chosen in the Sequence Model card. See Help for what each field means.
Sequence Model — classify a de-interleaved pulse train
Classifies a window of k consecutive pulses of one emitter, so it can use the PRI pattern (ΔPRI) and frequency agility (Δfrequency) over time. Trains on the Sequence Dataset (Dataset page → Sequence Pipeline). Uses the Hyperparameters, Distance Metric and RPL settings from the form on the left. Every run appears in Run History for comparison. Test it on the Testing page.

Δ features are differences to the previous pulse of the same track (ΔPRI exposes stagger / sliding / jitter; Δfrequency exposes agility; ΔPW mostly marks mode switches). Frequency is in MHz and bandwidth in Hz in the files (the model is fed Hz and MHz respectively). Modulation type and your own text columns are fed as numbers (one value per category). Each feature is standardized (x − μ)/σ on the training tracks.
Per class (never per pulse), Test split % of the tracks are set aside and kept for the Testing page. The rest is cut into Folds equal buckets; fold f validates on bucket f and trains on the others, so every track validates once — with 20 % test and 4 folds that is 20:20:20:20:20, three buckets training, one validating, the fifth the untouched test split. The model of the fold with the highest validation accuracy is kept; the run's accuracy and AUROC are the mean over the folds (± std) — the kept fold's own score is the best of several and would overstate it. Training takes about folds × as long. Tick Also train on the test split to use those tracks for training too (e.g. a final model) — the Testing page then marks the split as not independent.
Each sequence model gets its own thresholds. Auto sets τ_d so that the chosen share of known validation windows lie within it of their nearest prototype — calibrated on known data only (no unknown tracks involved), so the open-set results stay honest. Lower % = stricter (more unknowns caught, more known windows rejected). The chosen values are stored with the run; Testing can try others without retraining.
Add New Families — Incremental Training
A deployed model meets an emitter family it was never trained on (it flags it as unknown). Once its tracks are labelled, teach the model the new family without starting from nothing. Each method below makes a new model (a child of the base model, shown as “← #base” in Run History); the base model is never changed. All methods are scored on the same held-out tracks: the base model's own validation tracks (did it forget the old families?), a share of the new family's tracks (did it learn the new one?) and unknown tracks (does it still reject what it doesn't know?).
Simulate new-family data for this base model
Fresh tracks of families the base model was trained without (its held-out families, from the same simulated population), labelled with their names — plus the remaining held-out families and noise as unknown tracks. Stored as a new dataset. With your own data, upload the new family's labelled tracks on the Dataset page instead (families are matched by their true_label name).

A — the new family's classifier row is set to the average feature of its tracks and its prototypes are added; nothing is trained, no old data needed, old rows and thresholds untouched (but the new row competes with them). B — a few epochs from the base weights on the new tracks plus a small replay buffer of stored tracks of every old family; prototypes recomputed and τ_d recalibrated. C — a few epochs on the new tracks only; the base model is kept as a “teacher” and the new model must keep its outputs on the old families and its embeddings (distillation, Learning without Forgetting); old families' prototypes can only be kept from the base model. D — everything retrained from scratch on all old training tracks plus the new tracks: the reference the others are measured against.
